曾经，每次想写点什么，我都会先折腾博客。挑框架、配主题、接插件，再花一个晚上处理构建错误。等一切准备妥当，最初想说的话反而忘了。

这一次，我想从一个更小的问题开始：**一篇文章，需要多少技术才能被阅读？**

## 页面本来就可以很简单

浏览器已经知道怎么显示标题、段落和链接。服务端返回一份完整的 HTML，读者就能开始阅读，不需要等待 JavaScript 下载，也不需要 hydration。

> 好的工具，让你更接近想做的事。

这个小站只做三件事：读取 Markdown，用 Goldmark 转成 HTML，再交给 Go 的 `html/template` 装进页面。结果是一组普通文件，可以放到任何静态托管服务上。

```text
content/posts/*.md
        ↓ Goldmark
     文章 HTML
        ↓ html/template
      public/
```

## 把复杂度留在构建时

运行下面这条命令，文章就变成了可以发布的网页：

```sh
go run .
```

想在本地看看效果，再启动一个预览服务器：

```sh
go run . -url http://localhost:8080 -serve localhost:8080
```

不需要安装前端依赖，也没有打包步骤。构建结束后，线上甚至不需要运行 Go；它只负责提前把页面准备好。

| 需要的东西 | 选择 |
| --- | --- |
| 写作格式 | Markdown |
| Markdown 解析 | Goldmark |
| 页面模板 | html/template |
| 样式 | 一份 CSS，系统字体 |
| 客户端 JavaScript | 0 字节 |

## 对人友好，也对机器友好

标题用真正的标题元素，列表中的发布时间放在 `time` 里，正文放在 `article` 里。搜索引擎和 Agent 请求一个 URL，就能直接获得完整内容。

RSS 提供全文订阅，sitemap 列出页面地址。这些都是安静、成熟的协议，不会催促任何人打开通知。

简单也有边界：这个博客没有站内搜索和评论系统。目前文章不多，一页清晰的列表已经足够。如果以后需要，再从实际问题出发。

## 留一点空白

视觉上，我喜欢细边框和清晰的文字层级。首页直接展示文章列表，绿色只在少数地方出现。没有需要加载的网络字体，没有为了装饰而下载的大图。

速度不是某一个永远不变的分数。网络、托管和后续内容都会影响它。能做的是让起点足够轻，让每一个新增依赖都有充分的理由。

小站已经能用了。接下来，更值得花时间的事是写下一篇。
