# 写文章

这个博客的核心是简洁：一份完整的 HTML，默认 0 JS，没有组件。文章只能用下面列出的语法；做不到的效果就换一种写法，而不是给站点加功能。

## 文件

`content/posts/<slug>.md`，slug 只用小写字母、数字和单个连字符，并作为 URL `/posts/<slug>/`。用 `go run . new -slug <slug> -description "…" -tag <分类> "标题"` 创建，或手写：

```markdown
{"title":"标题","description":"一句话摘要，出现在首页、RSS 和 meta description。","date":"2026-10-24","tag":"折腾","tags":["Linux","Laptop"]}
---
正文第一段。
```

- 第一行是单行 JSON，再单独一行 `---`。`title`、`description`、`date`（`YYYY-MM-DD`）必填，`tag` 是分类，只有一个；`tags` 是标签列表，各自生成 `/categories/…/` 和 `/tags/…/` 页面与 RSS。`"draft":true` 不发布（`go run . -drafts` 预览）。英文版放在 `content/posts/en/` 下、用同一个文件名，两边会互相链接。修改已发布文章的实质内容时加上 `"updated":"YYYY-MM-DD"`；改错字不用。
- 正文不要再写 `# 标题`：页面已用 `title` 作 h1。正文从 `##` 开始，`##` / `###` 自动进入目录。
- 改 slug 或迁移旧文章时，把旧地址写进 `"aliases":["/旧/路径/"]`，第一项也是 RSS guid，已有的别名不要删。
- 没有草稿：`content/posts/` 下的文件都会发布。未完成的文章放在仓库外。
- `description` 要说清读者能得到什么，不要写口号；60–120 字为宜。它同时是搜索结果摘要和分享卡片文字（分享卡片没有图片）。

## 能用的语法

| 需要 | 写法 |
| --- | --- |
| 段落、列表、引用、链接、表格、删除线、任务列表 | GFM |
| 代码 | 围栏代码块并标明语言（`go`、`sh`、`ini`…），构建时高亮；配置片段没有合适语言就不标 |
| 公式 | 行内 `$…$`，独立公式 `$$` 各占一行；只用 treeblood 支持的命令，`\arg` 写作 `\mathrm{arg}` |
| 字面的美元符号 | `$5`、`$10` 这类价格自动保持原样；会被误认成公式时写 `\$` |
| 图片 | 原图放 `content/images/`，正文写 `![说明图片内容的替代文字](../images/name.png)` |
| 数据对比 | ```` ```data ```` 表格（见下文） |
| 图表 | ```` ```chart line/area/bar/scatter ```` （见下文），构建时画成静态 SVG |
| 指标卡 | ```` ```stats ```` （见下文） |
| 源码引用 | 代码块加 `src="<GitHub blob 永久链接>#L76-L103"`，可加 `title="…"`；显示路径、行号和 commit |
| 行情 | 单独一段 `::tv EXCHANGE:SYMBOL 说明文字 interval=W height=480`，或只写 `$BTC`（常见币种自动对应 Binance USDT 交易对）；生成行情卡片，读者点「实时图表」才加载 TradingView |

不可用：原始 HTML（`<br>`、`<details>`、`<img>` 都会被丢弃）、MDX/JSX 组件、脚注、`[!NOTE]` 提示块、除 `::tv` 以外的 `::directive`、Obsidian 的 `![[…]]` 嵌入、ECharts 之类需要脚本的图表（用 ```chart，悬停会显示数值）。

## 数据表格

图表在这里写成表格。每张表回答一个问题；读者应该能在 5 秒内从横条看出答案。

````markdown
```data title="12 档 delta 的 Sharpe 对比" bars="BTC,ETH" mark="Δ0.35" note="周频收益 × √52 年化。"
Delta | BTC  | ETH
Δ0.05 | 4.40 | 1.18
Δ0.35 | 3.43 | 2.19
```
````

- `title`：表回答的问题，写成名词短语，不加句号。
- `note`：单位、口径、样本区间、数据来源。表头放不下的单位放在这里。
- `bars`：只给可比较的数值列。同一单位的列共用比例（默认）；单位不同（如 BTC 与 ETH）加 `scale="column"`，并在 `note` 说明比例各自独立。
- `mark`：强调正文正在讨论的行，最多两三行。
- 第一列是行标签；数字带上符号和单位（`+0.112`、`-10.5%`），保留相同小数位。不要把多个数字塞进一个单元格。
- 单元格是纯文本。链接、代码、强调放在表外的正文里。
- 只有文字或数值不需要比较大小时，用普通 GFM 表格，数字列用 `---:` 右对齐。

## 图表

和 `data` 一样的管道表格：第一列是 x（`YYYY-MM-DD` 日期、数字或分类），其余每列一条序列。

````markdown
```chart line title="35Δ 累计 PnL（币本位，单利）" note="每周五入场。"
周五 | BTC | ETH
2022-09-02 | -0.001 | -0.006
```
````

- `line` 折线（日期 x 时末端自动标数值）；`area` 面积；`bar` 柱状（单序列正负两色，多序列并排）；`scatter` 散点，三列为 标签 | x | y。
- `panels="true"`：每条序列一格，各自 y 轴、共用 x 轴，适合量级不同的两条序列。
- `mirror="true"`：两条柱状序列背对背，第二条向下。
- `diag="true"`：散点加 y = x 参考线；`mark="标签,…"` 标注散点。
- `ref="62315,65217"`：竖直参考线。`xfmt` / `yfmt` 是 printf 格式（如 `yfmt="%.0f%%"`），`xscale` 先乘再格式化（`xfmt="$%.0fk" xscale="0.001"`）。
- 柱状图和面积图自动标出最极端的一点。几百行的逐周数据可以直接画；需要逐行读数时仍用 `data`。

## 指标卡

````markdown
```stats title="35Δ 周末卖方策略" meta="Deribit · 208 周"
## BTC 单利币本位
总收益 | +1.166 | +116.6%
胜率 | 81.25% | 169 / 39 周
```
````

`## ` 开始一组（第一个词加粗），其余每行 标签 | 数值 | 说明；以 `+` 开头的数值用强调色。

### 把图表改写成表格

不要逐点照搬。先写出这张图想证明的一句话，再选能证明它的最少行数，一般不超过 20 行。

| 原图 | 改写 |
| --- | --- |
| 分类柱状图（≤ 20 类） | 每类一行，数值列加 `bars` |
| 长时间序列（逐日、逐周） | 按月、季度或年汇总，或只列关键节点（起点、峰值、谷底、终点），在 `note` 写清汇总方式 |
| 累计曲线 | 每期末的累计值一列，加上当期增量一列 |
| 回撤 / 水下曲线 | 列出最深的几次回撤：开始、谷底、恢复日期、深度、持续周数 |
| 直方图 | 合并成 6–12 个区间，频数加 `bars`；可补一列占比 |
| 饼图 | 按占比降序，一列数值一列百分比，百分比加 `bars` |
| 散点图 | 列出最极端或最相关的 5–10 个点，并在正文写出整体关系 |
| 理论曲线（如损益图） | 取关键横坐标：行权价、盈亏平衡点、两端和若干等距点 |

汇总必须从原始数据计算，不要估读图形。改写后核对：合计、极值、正文引用的数字都与表格一致。

## 写作

- 中文正文，中英文之间、数字与单位之间留空格；使用全角标点。
- 先给结论，再给过程。每段只说一件事；删掉开场铺垫和总结式空话。
- 少用加粗，一段最多一处。避免「值得注意的是」「总的来说」「赋能」这类套话，以及成串的排比和破折号。
- 代码、命令、路径、配置项用行内代码。引用外部源码时给出固定 commit 的 GitHub 永久链接，并只贴必要的几行。

## 完成前

1. `go run .` 构建成功（公式、`data` 表格、图片路径出错都会让构建失败并给出位置）。
2. `go test ./...` 通过。
3. 用 `go run . -url http://localhost:8080 -serve localhost:8080` 打开文章，桌面和 390 px 宽各看一遍：目录、表格、公式、代码块没有溢出页面。
